# 指标密度规则

布局不按固定卡片数量排版，而按信息密度和业务主题排布。

槽位只表示位置意图和优先级，不是固定内容容器。必须先分析指标：主指标进入中心或视觉重心，其他指标按优先级和业务关系分布到左右、上下、底部、页签或下钻区域。

## Auto 布局选择必须 data-first

用户未说明布局时，不能直接使用网格布局。必须先得到数据结构，再选择布局。

```text
1. 用户提供指标：先分析指标类型、主次关系、业务对象和数据密度。
2. 用户通常提供 6–15 项内容；未提供时先 mock 8–12 个混合业务模块，再分析这些模块。
3. 用户提供少于 6 项：按业务合理补充 inferred/mock 辅助模块，除非用户明确禁止补充。
4. 用户提供多于 15 项：先合并业务主题，再决定首屏、页签、轮播、下钻。
5. 根据分析结果选择 layout_type；balanced_metrics_layout 只能作为最后兜底。
```

布局判断优先级：

```text
地图/区域/点位 → map_command_layout
园区/工厂/楼宇/3D/数字孪生/场景 → center_scene_layout
设备/产线/能耗/运行参数/故障维护 → equipment_monitor_layout
订单/工单/审批/流程/任务流转 → business_process_layout
总额/总数/完成率/目标达成/核心指标 → kpi_focus_layout
资讯/视频/党建/文旅/展厅/宣传 → content_portal_layout
超宽/大屏墙/多系统综合指挥 → ultra_wide_command_layout
以上均不明显 → balanced_metrics_layout
```

## 密度分级

```text
少量指标：
主视觉扩大，只保留核心指标和关键状态。

中等指标：
主视觉保持第一焦点，周边按业务主题分组。

多量指标：
先合并主题，例如运行概况、设备状态、告警事件、趋势分析。

极多指标：
首屏只放高优先级内容，中低优先级按业务关系进入页签、轮播、弹窗或下钻。
```

## 主题分组优先

示例：15 类数据不等于 15 个独立卡片。应先合并成 4 到 6 个业务主题组，再决定每组使用 KPI、图表、列表或页签。

常见分组示例，不能作为固定区域要求：

- 总览指标
- 趋势分析
- 分类构成
- 状态监控
- 告警事件
- 任务进度
- 排名对比
- 明细列表

## 禁止项

- 不允许把所有指标平铺成同等权重。
- 不允许因为指标多就压缩主视觉到不可识别。
- 不允许固定左侧、右侧、底部必须放几个卡片。
- 不允许在 `layout_type:auto` 时跳过指标分析直接生成均衡网格。
